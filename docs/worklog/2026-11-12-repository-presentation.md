# Credibility through inspectable evidence

**Outcome:** Present the adapter as a usable community alpha whose claims visitors can check.

- **Trust signals must be earned.** Link the published gem, real CI matrix, fresh-app installation evidence and dated sandbox observations. Avoid invented adoption, coverage percentages, audit claims or official endorsement.
- **Show the running product.** Use actual screenshots of the deployed Rails demo with synthetic billing records. Keep local simulations visibly distinct from provider-confirmed behavior.
- **Keep limitations discoverable.** Preserve alpha status, unsupported Pay/Stripe concepts and provider verification gaps rather than hiding them behind polished presentation.
- **Make participation practical.** Give contributors a reproducible local check and a private route for vulnerability reports, without promising response times or independent security certification.
