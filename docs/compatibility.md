# Pay compatibility

`pay-whop` is an alpha adapter for Whop's billing model. It does not claim parity with every Stripe feature. The raw SDK is available for Whop services outside payment processing.

| Pay / billing operation | Whop adapter behavior |
| --- | --- |
| `set_payment_processor`, customer association | Seller/environment-scoped Whop member identity, signed references |
| Hosted checkout | Existing or inline variants; one-time, recurring and setup |
| `charge`, `subscribe` | Saved method required; incomplete payments raise `PaymentIncomplete` |
| Authorization, capture, void | Full capture; fresh paid state required for Pay charge |
| `refund!` | Full/partial, exact currency precision, asynchronous confirmation |
| Cancel, cancel now, resume | Scheduled cancellation, immediate end, reversal of scheduled cancellation |
| Pause, unpause, free days, promo code | Dedicated Whop operations, actual provider state refreshed |
| Failed payment retry | Existing membership payment only; no replacement order |
| 3DS / action required | Provider recovery URL plus verified webhook completion |
| Renewal price / cadence / date | Price reductions and permitted changes; provider eligibility applies |
| Saved methods / default / replacement / detach | Member-scoped methods; local default; explicit subscription replacement |
| Customer billing portal | Existing membership's management URL |
| Draft/issued/paid/void/past-due/uncollectible invoices | Separate invoice summary; paid invoices create charges; issuance currently verification-blocked in this sandbox |
| Dispute preparation, evidence, submit, accept | HTTP-tested wrappers; no real dispute certification |
| One-time membership access | Separate entitlement with status/expiry, not `subscribed?` |
| `pay_merchant`, seller onboarding | Child account parent validation, hosted onboarding, fresh capabilities |
| Marketplace charges / application fees | Separate seller-scoped buyers and signed child webhooks |
| Internal transfers | Idempotent requests and separate settlement state; this sandbox still verification-blocked |
| Balances and payout status | Read/reconcile; payout initiation through hosted portal; no bank settlement proof |
| Webhooks / app callbacks | Signature validation, persisted IDs, account checks, fresh API reads, at-least-once callbacks |
| Recovery / backfill | Pending-delivery recovery job and linked-customer/merchant reconciliation |
| Emails / receipts | Whop messaging; Pay receipt/subscription emails are not generated by this adapter |
| Plan swaps / Stripe-style proration | Unsupported; price/cadence changes are narrower operations |
| Recurring seat quantity / metering | Unsupported; quantity remains 1 |
| Ended recurring reactivation | New checkout required; one-time entitlements have a separate reactivation API |
| Direct bank payouts / FX / tax accounting | No direct withdrawal creator or general accounting reconciliation |
| Whop chat, ads, cards, affiliates, trading | Outside this adapter; use the official SDK |

Implemented does not mean validated against real money or every provider state. [Verification evidence](verification.md) separates automated tests, sandbox observations and remaining limitations. [Advanced usage](advanced-usage.md) documents method signatures and provider restrictions.
